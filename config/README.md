# Где хранятся настройки

Настройки делятся по владельцу правила и жизненному циклу, а не по одному файлу на каждый параметр. Один параметр должен иметь один источник истины. При добавлении настройки сначала определить, к какой группе она относится, затем обновить типизированный загрузчик, проверку при запуске, тест и этот перечень.

| Группа | Где хранится | Что сюда относится |
|---|---|---|
| Поведение запущенного приложения | `config/runtime.yaml` | Расписание обновления, горизонты загрузки и прогноза, порог давности исторического курса. Без секретов и персональных данных. |
| Инвестиционная политика | `config/ips/personal_main.draft.yaml` | Иерархия IPS и целевые доли. Файл пока черновой, но приложение использует его для отображения структуры портфеля и доходов; рекомендации он пока не определяет. |
| Границы учета и классификация | `config/ips/portfolio_exclusions.yaml`, `config/ips/instrument_classifications.yaml` | Исключения из NAV/отчетов и исходные правила или данные классификации. Активный факт классификации хранится в PostgreSQL. |
| Учетные факты | PostgreSQL | Счета, позиции, операции, курсы, прогнозы, история классификации. Не хранить их в YAML или `.env`. |
| Секреты и окружение | `.env` локально, `/etc/invest-cons/invest-cons.env` на сервере | Токены, доступы, `DATABASE_URL`, идентификаторы допущенных пользователей, сертификатные пути и привязки счетов к владельцам. Шаблон: `.env.example`. |
| Контракты и инварианты | Код и тесты | Поля брокерских API, формулы, единицы измерения, допустимые состояния. Не делать их переопределяемыми без бизнес-причины. |

`config/runtime.yaml` читается один раз при старте; отсутствующий или некорректный обязательный параметр останавливает запуск. `schema_version` описывает формат этого файла, а не версию IPS. Не дублировать один и тот же параметр в YAML и переменных окружения. Для разового переопределения нужен явный CLI-флаг с документированным приоритетом.

Новый файл выделять, когда у набора настроек появляется отдельный владелец, независимое версионирование или отдельный процесс публикации. Для одного нового порога создавать отдельный YAML не нужно. При изменении финансовой методологии отдельно фиксировать версию расчета и влияние на исторические результаты.
