# Протокол тестирования и сверки

Этот файл определяет процедуру; результаты реальных сверок заполняются по мере выполнения. Не публиковать в репозитории номера счетов, токены, полный брокерский отчет и персональные данные.

## Автоматические уровни

| Уровень | Что проверяем | Где сейчас |
|---|---|---|
| Unit | Чистые функции: цена и количество, НКД, FX, неполный счет, внешний поток, Modified Dietz, XIRR, статусы выплат. | `tests/test_portfolio_v2_domain.py` и смежные тесты. |
| Contract | Преобразование обезличенных ответов T-Invest/Freedom, пагинация, отсутствующие поля, повтор и пересмотр операции. | `tests/test_portfolio_v2_adapters.py`; покрытие расширять на реальные варианты ответа. |
| Integration | Чистая БД, сохранение/чтение снимка, идемпотентный импорт, интервалы операций, миграции. | `tests/test_portfolio_v2_storage.py`; для миграций тесты добавить после их появления. |
| End-to-end | Локальный refresh и команды бота на тестовом наборе счетов с явным контролем качества. | Ручная проверка, автоматический безопасный сценарий еще не оформлен. |

Запуск без реальных API описан в [commands.md](commands.md). Проверка `--refresh-once` вызывает внешние источники и не является заменой автоматических тестов.

## Ручная финансовая сверка

Для согласованной даты и каждого счета отдельно зафиксировать в приватном протоколе: брокер, псевдоним счета, дата и зона времени, число позиций, количество каждой бумаги, cash по валютам, брокерскую стоимость, нашу стоимость, источник FX и разницу. Затем сверить общий NAV в RUB/USD с указанной методикой конвертации. Допуски округления определить и записать **до** признания расхождения приемлемым.

Для выбранного интервала сверить: начальный/конечный NAV, каждый внешний ввод/вывод с датой и валютой, переводы между своими счетами, купоны/дивиденды, абсолютный P&L. Отдельно проверить, что повторная синхронизация не удвоила операции, а ошибочный счет или неизвестный FX блокирует зависимый итог.

Для прогноза проверить три случая: объявленный платеж, расчетная оценка и отсутствие надежного источника. Событие после продажи бумаги не должно задним числом изменять факт выплаты.

## Запись результата

Для каждой сверки сохранять без чувствительных данных: ID проверки, дату, версию кода/метода, обезличенный набор счетов, интервал, ожидаемые и фактические величины, установленный допуск, итог `pass/fail/incomplete`, причину расхождения и ссылку на исправление. Сырые подтверждающие выгрузки хранить вне Git с ограниченным доступом. Только `pass` по согласованному охвату переводит функцию в статус `verified`.

Обязательные регрессионные кейсы: `GetAccounts` успешен, `GetPositions` вернул ошибку; у Freedom появился `intercompany` или неизвестный тип; нет курса на дату; один брокер недоступен; повторные операции; изменение состава счетов; купон после продажи; на входе нулевой/отрицательный NAV; несколько корней XIRR.
