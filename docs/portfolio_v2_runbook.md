# Портфель V2: запуск и ограничения технического среза

Реализация изолирована от `main.py`, старого бота и старых таблиц. Таблицы создаются в схеме PostgreSQL `portfolio_v2`; остальные схемы не меняются. Для бота нужен **отдельный Telegram token**: два polling-процесса на одном token одновременно запускать нельзя.

## Конфигурация

Используются существующие `DATABASE_URL`, `INVEST_TOKEN_READ`, `INVEST_CLIENT_LABELS`, `FREEDOM_TRADERNET_PUBLIC_KEY`, `FREEDOM_TRADERNET_PRIVATE_KEY`, `FREEDOM_TRADERNET_DOMAIN`, `FREEDOM_CLIENT_LABEL`, а также настройки корневых сертификатов T-Invest. Оба брокера обязательны: если ключей одного нет, процесс не стартует.

Дополнительно в `.env`:

```dotenv
PORTFOLIO_V2_TELEGRAM_TOKEN=<отдельный token нового бота>
PORTFOLIO_V2_TELEGRAM_IDS=123456789
PORTFOLIO_V2_OWNER_MAP={"Mike":"owner_mike","Marina":"owner_marina","Freedom":"owner_mike"}
# Только после ручной проверки статуса счёта у брокера:
# PORTFOLIO_V2_EXCLUDE_ACCOUNTS=1234567890
```

`PORTFOLIO_V2_TELEGRAM_IDS` задаёт список числовых Telegram user ID. Сейчас каждый ID видит всю совокупность счетов; разграничение по владельцам в боте ещё не реализовано. `OWNER_MAP` привязывает метки T-Invest/Freedom к стабильным идентификаторам владельцев. Не публикуйте `.env` и raw брокерские события.
`PORTFOLIO_V2_EXCLUDE_ACCOUNTS` исключает из охвата лишь явно перечисленные ID счетов T-Invest. Не используйте его для подавления ошибки без сверки: изменение охвата создаёт новую временную серию, несопоставимую со старой без специальной обработки.

## Запуск

```powershell
.\.venv\Scripts\python.exe run_portfolio_v2.py --refresh-once
.\.venv\Scripts\python.exe run_portfolio_v2.py
```

Первый запуск подтягивает 90 дней операций. Последующие запуски берут дату последней успешной синхронизации с двухдневным перекрытием. Снимки остаются в PostgreSQL после перезапуска. Для ежедневного обновления можно вызывать `--refresh-once` внешним планировщиком; одновременно с ботом эту команду пока не запускайте, межпроцессной блокировки нет.
`--refresh-once` завершится кодом 2, если последний снимок неполный или синхронизация операций требует разбора. Код 0 означает успешную техническую загрузку, но не заменяет ручную сверку оценок с брокером.

Команды: `/start`, `/refresh`, `/portfolio`, `/performance`, `/income` (`/income_report` — alias). Доходность рассчитывается в RUB и USD между самым старым полным снимком в пределах последних 30 дней и последним полным снимком, если доказан охват операций. Формула абсолютного результата: конечный NAV минус начальный NAV минус чистые внешние потоки. В процентах показываются Modified Dietz и годовая XIRR. TWR в этой версии нет. До появления второго полного снимка доходность недоступна. Отчет `/income` показывает факт с начала года и месяца, прогноз до конца года и месяца; drill-down по IPS продолжается до позиции и счета. Кнопка обновления в income запускает синхронизацию в фоне, обновляет отчет и меняет статусное сообщение по завершении. Фактические операции при первом refresh догружаются с 1 января, прогнозные события обновляются там же из календарей брокеров. В отчете применяются исторический FX для факта и текущий FX для прогноза; отдельная налоговая корректировка сумм отсутствует.
Для расчёта нужен интервал не менее суток. `/performance` показывает общую совокупность и отдельно T-Invest/Freedom: ошибка одного брокера блокирует общий итог, но не подтверждённый результат другого. Неразобранные `intercompany` блокируют лишь периоды, в которые они попали.

## Контроль качества и известные ограничения

- Перед доверием NAV нужна ручная сверка по каждому счёту с брокерским итогом: количество T-Invest берётся в штуках, цена за штуку, по облигациям НКД прибавляется отдельно; для Freedom используется `ps.pos.s` и `ps.acc.s` в валюте записи. Если смысл `ps.pos.s` у конкретного инструмента иной, требуется коррекция адаптера.
- Если валюта НКД и цены T-Invest различается, они конвертируются отдельно на дату снимка. Стоимость в одной исходной валюте для такой бумаги помечается как `н/д`; оценки RUB/USD остаются доступными при наличии обоих курсов.
- При проверочном чтении один из заявленных T-Invest счетов вернул `GetPositions: Account not found`, хотя был получен через `GetAccounts`. Он оставлен в охвате со статусом ошибки; до выяснения причин общий NAV недоступен. Исключать его через конфиг можно только после проверки у брокера.
- Курс ЦБ на дату события сохраняется с источником; валютный прогноз пересчитывается по текущему FX и не является гарантированной RUB/USD выплатой. Если курса/цены нет, NAV или результат остаются `н/д`, не нулём.
- Freedom `bank` рассматривается как внешний поток. `intercompany` и неизвестные типы сохраняются как `unresolved` и блокируют доходность за затронутый период до ручной классификации. Весь брокерский отчёт сохраняется как raw event, включая `trades`; сделки пока не нормализуются отдельно.
- Купонный прогноз Freedom получен из параметров бумаги и имеет статус `estimate`; для T-Invest используются календарь облигаций и календарь дивидендов. Календарь дивидендов Freedom пока недоступен; расчетная оценка по forward dividend yield не перенесена. Факт дивидендов из брокерского отчёта требует сверки на реальном периоде. Ошибки календаря и неполный охват видны в `/income`; прогноз сохраняется только после обновления.
- Нет межпроцессного lock, разграничения доступа по владельцам, полноценного TWR и сверки сохранённых raw событий с исправлениями отчёта брокера. Встроенный ежедневный планировщик работает только пока запущен процесс бота. Схема сейчас инициализируется idempotent DDL при старте; перед облачным развёртыванием её следует оформить отдельной версионированной миграцией.
- По этим причинам код является работающим техническим срезом, а не принятым инвестиционным учётом. Без сквозной сверки двух брокеров реальные общие RUB/USD доходности могут оставаться недоступными.
