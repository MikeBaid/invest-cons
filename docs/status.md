# Статус разработки

Дата фиксации: 2026-10-04. Этот документ различает: `planned` - описание без реализации, `implemented` - код есть, `verified` - подтверждено тестами и согласованной сверкой на реальных данных, `blocked` - есть препятствие для приемки. Результат отдельного теста не подтверждает весь учетный сценарий.

Автоматические тесты: 34 прошли, 1 интеграционный PostgreSQL-тест пропущен (требует явного включения). Команда и ограничения среды описаны в [commands.md](commands.md).

Всего 71 активное назначение в PostgreSQL. Новые неизвестные позиции видны как `Без классификации`. Дерево IPS загружается из YAML, целевые веса остаются draft. |

Локальный тестовый бот: реализована отключенная по умолчанию команда `/classify` и кнопка в карточке неклассифицированной позиции. Администратор выбирает путь по дереву IPS, подтверждает только лист; назначение сохраняется в `classification_history` с источником `telegram_manual`. Повторный импорт preview сохраняет эти решения. Unit-тесты пройдены; реальный Telegram/PostgreSQL-сценарий пока не проверен. Для запуска нужны `PORTFOLIO_V2_CLASSIFICATION_ENABLED=true` и `PORTFOLIO_V2_CLASSIFICATION_ADMIN_IDS` в локальном `.env`; серверный бот по умолчанию не меняется.

Preview 2026-10-04 содержит 88 строк, все получили подтверждённые листы; назначения дедуплицированы до 69 записей, плюс два пользовательских решения для NDM и `FPSTB5.KZ`. Снимок неполон, цифрового счёта в нём нет. Изменение IPS добавило прежние 4% к `external.bonds.kz_fx` (итоговая цель KZ FX 4%, external bonds 15%). В неполном snapshot фактические доли рассчитываются от наблюдаемого NAV; целевые суммы также масштабируются от него и не выдаются за цели полного портфеля. Ежедневный таймер и ручная кнопка реализованы, проверка работы в постоянно запущенном процессе бота ещё нужна.

Ближайшие действия для приемки: разобрать недоступный счет T-Invest; классифицировать спорные события Freedom; сверить количества, остатки, NAV и выплаты; затем закрыть доступ по владельцу. Структурный рефакторинг и миграции делать после фиксации поведенческих тестов. Проверенные команды находятся в [commands.md](commands.md).
