# Эксплуатация и развертывание

## Текущий технический срез

PostgreSQL работает локально через `compose.yaml`; бот запускается отдельным процессом. Пока этот процесс работает, ежедневный refresh выполняется по `config/runtime.yaml` (сейчас 06:00 `Europe/Moscow`). Если процесс остановлен в это время, пропущенный запуск автоматически не догоняется. Ручной refresh выполняется командой `/refresh`; в отчете `/income` также есть кнопка фонового обновления. Таймер и ручной refresh используют один `PortfolioService` и сериализуются его lock. Одновременно на одном Telegram token должен работать только один poller; отдельный CLI `--refresh-once` не имеет межпроцессного lock и не должен запускаться одновременно с ботом. Исполняемая схема `portfolio_v2` создается из `storage.py` при старте.

Параметры подключения и токены берутся из `.env` по `.env.example`. Доступные команды и значения кодов завершения - в [commands.md](commands.md). Токены брокеров должны быть read-only. Ошибка или частичный ответ источника сохраняется как ограничение качества; не «лечите» ее исключением счета без проверки у брокера.

## План безопасного переноса в облако

Подробный проверяемый runbook, требования к VPS, сравнение провайдеров, команды и разделение действий Codex/владельца: [server_deployment.md](server_deployment.md).

1. Создать версионированные миграции схемы и проверить их на пустой и существующей базе. Импорт данных - отдельная идемпотентная команда.
2. Настроить раздельные секреты и доступы для бота, фонового процесса и миграций; подключение к локальному/облачному PostgreSQL различается только конфигурацией.
3. Добавить межпроцессный lock синхронизации, EOD-задачу, healthcheck и наблюдаемость по успешности/полноте каждого брокера и счета.
4. Определить политику хранения raw payload, логов и резервных копий; ограничить доступ к персональным данным.
5. Проверить восстановление резервной копии в отдельном окружении и повторную загрузку без дублей. Только затем переключать рабочую базу.

## Резервное копирование и восстановление

Пока автоматическая процедура не реализована и не проверена. Перед изменением схемы/развертыванием нужен согласованный backup PostgreSQL вместе с проверкой восстановления в отдельную БД. Само наличие файла backup не подтверждает восстановимость. Фиксировать дату, версию схемы, число снимков/операций до и после восстановления и ответственного. Не публиковать резервные копии в Git или общедоступные артефакты.

При сбое внешнего источника сохранять предыдущие проверенные данные, но показывать их дату и устаревание. Не выдавать старые прогнозы как свежие и не рассчитывать общий результат из неполного набора счетов.
